## Findings

### Important — ADDRESSED in scoped fix below: runtime selection performs pointer arithmetic across distinct LDS arrays

`csrc/fp8_native.hip:1797` (also lines 1836, 1902, and 1941) adds `sm.value_offset(base + k)` to `invariant_vbase`, a pointer formed from `sm.v0` at line 1608. The arrays remain distinct objects at lines 1503–1504. For slot 1, the offset is the numerical address difference `v1 - v0`; adding it to a pointer into `v0` crosses the bounds of that object. Slots 2 and 3 have the same problem. Preserving the numerical correction formula does not make this cross-object pointer arithmetic valid.

The retained integrated-suite IR at `/tmp/pytest-of-jinpli/pytest-80/native_order0/native.ll` corroborates the provenance issue: lines 53–56 and 62–65 declare the separate V globals, lines 309–311 form the d128 invariant from `v0`, and lines 7438–7440 form the selected pointer with a GEP chain based on that invariant. Those selected GEPs are **not** marked `inbounds`; nevertheless their pointer origin remains `v0`. DS reads and subsequent `inbounds` fragment GEPs consume that pointer at lines 7753 onward. The other three d128 updates and all four d192 updates use the same construction. Passing machine-code checks establish the current executable's observed behavior, but do not establish valid source-level pointer arithmetic or allocation provenance.

Use the existing numeric-address convention of `Lds::value()`: retain the complete invariant as `uint32_t`, add the actual-array-derived offset in `uint32_t`, and convert the final numerical address to `byte_lds`. Keep all four array identities, both correction terms, sharing sites, and last-pass selection placement. Verify the corrected retained IR and actual object; if executable text, descriptors and metadata remain byte-identical, tie the existing GPU/timing evidence explicitly to that same binary and refreshed source provenance.

### Minor — shared input register names do not prove a shared invariant definition in the committed regression

`tests/test_fp8_hip_codegen.py:256` checks that all four selected-address updates name one input VGPR. It does not trace the reaching definition of that input. This is the previously recorded nonblocking regression-hardening recommendation, not a new defect in the reviewed object. The corrected task CFG audit and `verify-integrated.py:108`–122 independently establish exactly one entry definition for the actual owning object. Strengthening the permanent regression can remain deferred; it does not require a second fix wave.
