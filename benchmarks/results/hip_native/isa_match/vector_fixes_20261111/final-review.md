## Source and arithmetic correctness

- `csrc/fp8_native.hip:306` factors the four original transposed DS reads into `read_v_fragment`. Their offsets, packed return order, and optional schedule fences are unchanged. The existing `read_v` interface retains constant-slot callers and their allocation-aware `Lds::value` selection.
- `csrc/fp8_native.hip:492` computes the complete runtime V address once per `pv` invocation. Every fragment retains its original Half/J arguments. All read-ahead, pending-count waits, prefetch callbacks, probability inputs, MFMA ordering, and accumulator ordering remain unchanged. The address is a local value derived from the same LDS pointers and lane expression; it introduces neither an LDS contiguity assumption nor mutable state across pipeline steps. Normal, PV-only, and last paths still select `(base + k) & 3` or the equivalent current-slot expression.
- The setup expressions at `csrc/fp8_native.hip:1571` and `csrc/fp8_native.hip:1602` use the standard HIP `__umul24` operation and remove only the intermediate product anchors. Chunk, index, and final-offset anchors remain. No compiler, build flag, emitted-assembly patch, large inline assembly, or fixed-register workaround was introduced.
- The fixed 512-thread launch bounds K keys to 0..127/0..63. The V key bitfields independently give maxima `96 + 4 + 16 + 8 + 3 = 127` and `32 + 4 + 16 + 8 + 3 = 63`. The native guards at `csrc/fp8_native.hip:2038` and `csrc/fp8_native.hip:2044` reject unsigned K/V strides at or above `2^24` before launch configuration or error-state access; d192 checks K and V independently. Thus both multiply operands fit unsigned 24 bits, and the final unsigned chunk addition equals the previous full-width expression. Maximum accepted setup offsets are below `INT_MAX`, so the existing signed stride locals and the HIP intrinsic's result representation cause no narrowing error in this domain.
- The public native wrappers already require nonempty `M = N >= 256` and `N * stride < 2^32`, establishing the new native bound for every previously accepted nonempty wrapper call. Query/output arithmetic is unchanged. Tiling, LDS arrays, four-slot staging, and two-wave pipeline code are untouched.
